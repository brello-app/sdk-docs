---
title: "Quickstart"
description: "Verify a project key and send a sample usage event."
---

See the [TypeScript quickstart](/typescript/quickstart) for OpenAI, Anthropic, Google AI Studio, and Vertex AI, or the [Python quickstart](/python/quickstart) for OpenAI and Anthropic.

You need a Brello project ingestion key and a shell with `curl`. These examples use the hosted API. If you run Brello yourself, substitute your deployment's origin and keep `/v1`.

<Steps>
  <Step title="Set your environment">
    Run these commands in Bash or Zsh. Use a test project key for the sample event.

    ~~~bash
    export BRELLO_API_KEY="YOUR_PROJECT_API_KEY"
    ~~~
  </Step>
  <Step title="Verify your key">
    ~~~bash
    curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' \
      --header "Authorization: Bearer $BRELLO_API_KEY" \
      "https://api.brello.app/v1/config"
    ~~~

    A `200` response verifies the project key. This example prints only the status because the response can include a project identity secret. See [configuration](/api-reference/config) for the available fields.
  </Step>
  <Step title="Send one sample event">
    Replace the timestamp with the completed-attempt time and generate a fresh UUID for every new event.

    ~~~bash
    curl "https://api.brello.app/v1/events" \
      --request POST \
      --header "Authorization: Bearer $BRELLO_API_KEY" \
      --header "Content-Type: application/json" \
      --data '{
        "schemaVersion": "1",
        "sdk": { "name": "http-example", "version": "1.0.0" },
        "events": [{
          "id": "019a9000-0000-7000-8000-000000000001",
          "type": "llm.request",
          "occurredAt": "2026-11-19T12:00:00Z",
          "durationMs": 850,
          "provider": "openai",
          "model": "gpt-4o-mini",
          "status": "success",
          "feature": "summarize",
          "endUser": { "id": "user_123" },
          "usage": { "inputTokens": 1200, "outputTokens": 300 }
        }]
      }'
    ~~~
  </Step>
  <Step title="Check the receipt">
    ~~~json
    {
      "data": {
        "requestId": "request-uuid",
        "receivedAt": "2026-11-19T12:00:01Z",
        "acceptedCount": 1,
        "rejectedCount": 0,
        "rejected": []
      }
    }
    ~~~

    A `202` response means valid events reached the queue. Inspect `data.rejected` for failed items. Processing and cost calculation happen later.
  </Step>
</Steps>

See [event fields](/guides/events) to adapt the payload to your application and [delivery and retries](/guides/errors) to handle partial acceptance and network failures.
